#+title: workflow-kit — Org-Native Artifact Layer for Spec-Driven Development

A Claude Code plugin that layers on obra/superpowers: Superpowers owns the process phases (the design brainstorm, TDD inner loop), this kit owns the artifact/record layer — the org document chain (PRD/DESIGN/PLAN/stories), verification ledger, and consistency passes. Design rationale lives in docs/workflow-alignment-plan.org; this repo's own editing rules live in CLAUDE.md.

* Install (plugin, recommended)

1. =/plugin marketplace add <github-user>/claude-workflow-kit=
2. =/plugin install workflow-kit@dustin=
3. In each project repo: copy the matching =project-setup/CLAUDE.md.{mvp,workgrade}= to =CLAUDE.md= and fill in project name, stack, commands, copy =project-setup/learnings.org= to =docs/learnings.org= and =project-setup/decisions.org= to =docs/decisions.org=, append =project-setup/.gitignore='s contents to the repo's =.gitignore=, and set the repo's default model to Sonnet with ={"model": "sonnet"}= in =.claude/settings.json= (create the file if absent). That is the entire per-repo setup — skills, agents, hooks, and templates all travel with the plugin.
4. Optional per-repo override: create a local =templates/= directory to shadow the plugin's templates for that project.
5. Optional, work-grade repos: wire =stop-test-gate.sh= into the repo's =.claude/settings.json= per the script header. It stays out of the plugin's hooks.json deliberately — plugin hooks fire in every repo where the plugin is enabled, and a mandatory test gate is a work-grade opinion, not a universal one. (prd-lock, post-edit-format and tidewave-preflight are safe globally: the first two self-gate on file patterns, and the third self-gates on the project having a Tidewave MCP server registered, never blocking anything either way.)

* Local development of the kit

- =claude --plugin-dir /path/to/claude-workflow-kit= loads the working copy for a session, taking precedence over the installed version.
- =/reload-plugins= picks up edits without restarting.
- =test/hooks_test.sh= must be green before any commit that touches hooks/ (CI enforces this on push/PR).

* Install (copy-in fallback, no plugin)

Copy =skills/=, =agents/=, =hooks/=, and =tools/= into a repo's =.claude/= directory, add =project-setup/copy-in-settings.json= as =.claude/settings.json= (it wires hooks via =$CLAUDE_PROJECT_DIR=), copy =templates/= to the repo root, copy =project-setup/learnings.org= to =docs/learnings.org= and =project-setup/decisions.org= to =docs/decisions.org=, append =project-setup/.gitignore='s contents to the repo's =.gitignore=, and =chmod +x .claude/hooks/*.sh=. Note the skills lose their =/workflow-kit:= namespace in this mode — invoke them bare (=/user-stories=).

* The pipeline

| Stage             | Invocation                                                      | Owner                       |
|-------------------+-----------------------------------------------------------------+-----------------------------|
| Idea → PRD        | =/workflow-kit:create-prd= (fires on a new-feature request)     | this kit                    |
| Design brainstorm | automatic (Superpowers), from PRD.org and SKETCH.org            | Superpowers brainstorming   |
| Design            | =/workflow-kit:promote-design=                                  | this kit (+ skeptic agent)  |
| Stories + plan    | =/workflow-kit:user-stories PRD.org DESIGN.org=                 | this kit                    |
| Implementation    | normal session, Superpowers TDD                                 | Superpowers                 |
| Story close-out   | =/workflow-kit:story-closeout stories/story-NN-*.org=           | this kit (+ verifier agent) |
| Doc consistency   | =/workflow-kit:update-design=                                   | this kit                    |
| Phase close       | =/workflow-kit:phase-close=                                     | this kit                    |

The weight-class section in each project's CLAUDE.md is the amplitude knob: it selects the DoD variant, toggles the skeptic review, and sets PRD length expectations. Skills and plugins set the shape of the process; CLAUDE.md sets the amplitude.

* A run, end to end

The table above lists what each stage is. This is what a human types, and where the stages hand off to each other.

1. =/workflow-kit:create-prd=, naming the idea — a sentence, or an entry in =docs/backlog.org=. Outcome altitude only; mechanism that comes up is parked in =SKETCH.org=. The run ends at one of four verdicts, and the one that continues writes =PRD-draft.org= into a new initiative directory.
2. *The human renames the draft*, moving =PRD-draft.org= to =PRD.org= in the initiative directory. That rename is the approval act — no skill performs it, and prd-lock blocks agents from writing the locked filename at all. The lock commit follows, doc-only, with =SKETCH.org= riding along.
3. =/model opus=, then *a fresh session* opened with "let's design <initiative>". No slash command exists for this stage: Superpowers' brainstorming fires on the phrasing, and the CLAUDE.md Workflow paragraph supplies the inputs — the locked PRD as the fixed contract, SKETCH.org as starting material. The fresh session is the point, not a formality: the brainstorm should meet the contract as a contract rather than remember negotiating it. Output stays in =docs/superpowers/specs/=, gitignored.
4. =/workflow-kit:promote-design= → DESIGN.org, presented with its alignment trace. The skeptic review runs at work-grade only.
5. =/workflow-kit:user-stories PRD.org DESIGN.org= → =stories/= and a new open batch in PLAN.org.
6. Per story, one story per session: TDD implementation, then =/workflow-kit:story-closeout stories/story-NN-*.org=, then =/workflow-kit:update-design=. All three, every story — close-out records the evidence, update-design keeps DESIGN and the unimplemented stories' excerpts truthful.
7. =/workflow-kit:phase-close= once the batch's last story is done.

Steps 2 and 3 are the ones that go missing, because neither is a skill invocation and so neither appears in the table. A hand-off that names =/workflow-kit:promote-design= straight after the PRD has skipped the design brainstorm.

* Stating the expected outcome of a skill run

A human prompt pattern, proven twice in live use: state the expected outcome of a skill run in the invocation itself, before it runs. That turns the run into a checkable prediction, and any deviation from the prediction becomes signal instead of noise. For example, invoking =/workflow-kit:update-design= with "expected: PLAN reconciliation only, NO DESIGN body edits; if you believe a body edit is warranted, surface the case before making it" gives the session a stated bar to run against, and the human a one-line check when it finishes. This is deliberately a human practice, not kit machinery — no skill encodes or checks the prediction, because the pattern only works when the human is the one stating the expectation.

* Notes

- *Namespace*: the =name= field in =.claude-plugin/plugin.json= defines the =/workflow-kit:= prefix. Renaming the plugin means updating the namespaced references in =skills/= and =project-setup/= — CI checks for this.
- *Model routing*: every kit stage pins its own model in frontmatter — =agents/skeptic-reviewer.md= and the architect-altitude skills (create-prd, promote-design, user-stories, update-design, phase-close) on =model: opus=; =agents/story-verifier.md= and story-closeout on =model: sonnet=, since audit work is mechanical (run the verify command once, cite test names and line numbers). A skill's pin is turn-scoped: it holds until the skill's turn ends, so a stage that stops to ask the human resumes on the session model afterward. The two stages the kit does not own — TDD implementation and brainstorming, both Superpowers — take the session model: the per-repo =.claude/settings.json= defaults it to Sonnet for builder work, and =/model opus= before a brainstorm is the one human routing step. Swap an alias for a specific model identifier (e.g. a Fable model string) if your plan supports it. Rationale in docs/fable-charter.org; =test/hooks_test.sh= lints the pins.
- *PRD lock, defense in depth*: the =prd-lock= hook covers file tools plus write-shaped Bash, and its block message teaches the Amendment protocol. A permissions deny rule on =PRD.org= can be added per-repo as belt-and-suspenders.
- *Tidewave pre-flight*: =tidewave-preflight.sh= is a SessionStart hook that probes the project's Tidewave MCP endpoint once, before any tokens are spent, so a session against a stopped dev server says so up front instead of discovering it at its first =mcp__tidewave__*= call. It finds the URL the way Claude Code does — =.mcp.json= in the project, then the per-project =mcpServers= entry in =~/.claude.json= — matching on the URL rather than the server name, so a Tidewave registered under another name is still found. No registered Tidewave means no probe and no output, which is every non-Phoenix repo. It is advisory: on trouble it injects context naming the URL and telling the session to ask the human to start the server, and it never blocks a call, never starts a server, and never waits more than two seconds. Down and listening-but-wrong (a different app on the port, or an sse/http transport mismatch) get different messages.
- *Iteration loop*: kit edit (from real project use) → CHANGELOG.org entry → version bump. The kit should shrink over time, not grow.
- *Story metrics*: =tools/story-metrics.py= reads this machine's Claude Code session transcripts, attributes sessions to stories, and prints the per-story table phase-close appends to =retro.org= — active minutes per phase, test runs, verifier dispatches, tokens, net lines. Run it by hand any time (=--list-sessions= shows the attribution); the numbers are heuristic and local to the machine the sessions ran on.
